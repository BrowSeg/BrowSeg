# M4 ロジット追跡のまとめ（2026-10-06 夜）

査読レポート M4（PENDING N9）。著者の GO（2026-10-06 夜）。対象は、肝臓 3 タスクで BrowSeg と参照（TS 2.18、CPU、デスクトップ）が食い違った IRCAD の 6 件（経路別では 8 件。対照として参照と一致した症例 14 の CPU 実行も追跡し、計 9 回）と、M3 の 4 組（デスクトップとノート PC の Python 版どうし）。

## 方法

| 側 | 方法 | 改造で結果が変わっていないことの確認 |
|---|---|---|
| BrowSeg CPU 経路 | プローブ版の WASM（`-DTSC_PROBE`、`web/dist-probe`、`build_wasm_probe.bat`）を Node で実行（`tests/probe_wasm_node.mjs`）。`SlidingWindow::accumulate` / `finish` で、指定した格子点の (a) タイルごとの fp32 出力とガウス重み、(b) fp16 の累積の前後、(c) 割り算後の最終値（肝内血管は元の格子に戻した値も）を出力 | 出力ラベルがベンチマークの記録（desk_chrome_wasm_20）と 6 件すべてでボクセル単位の完全一致 |
| BrowSeg WebGPU 経路 | 同じプローブ版を Chrome で（`bench.html?probe=`、`gpu_unet.js` の `forwardAccumulateProbe`：重み付けの前のネットワーク出力と、累積後の値を GPU から読み戻す） | 出力ラベルが記録（desk_chrome_webgpu_final）と 3 件すべてで完全一致 |
| Python 版 | `tools/probe_python.py`：nnU-Net の `_internal_predict_sliding_window_return_logits` を、同じ計算の逐次版に差し替えて同じ値を記録 | 出力ラベルが参照と 6 件すべてで完全一致。最終値が、別に保存した `{tid}_logits.npy` と全プローブ点で一致 |

プローブのコードは `@strip:probe` と `REPLACE` で公開版から除かれる（書き出し結果がプローブ導入前と全ファイル同一、識別子 0 件を確認）。比較は `scripts/compare_probes.py`、出力は `compare_<経路>_<組>.txt`。

共通する仕組み：畳み込みの足し算の順序の違いで、ネットワークの fp32 出力に数〜数十 fp32-ulp の差が出る → ある 1 枚のタイルの fp16 累積で丸めが 1 fp16-ulp 分ずれ、最後まで残る → 最終値の 1 ulp（14 は割り算で 2 ulp）の差が、もともと同点か 1 ulp 差の 2 構造の順位を入れ替える。ほかの格子点（各組 7 点、肝内血管 47 点）は最終値が完全一致。

注意：Python 側の「元の格子に戻した値」（crop プローブ）は、フックが呼ばれず記録されなかった。代わりに、Python 版のロジットを nnU-Net 自身の関数で戻した値（`tie_check_resampled.py`、argmax が 8_seg と 0 ボクセル差で再現）を使った。Python のネットワーク格子の最終値はプローブと保存ロジットで一致している。
